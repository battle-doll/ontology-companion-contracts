# Ontology Companion Contracts

[English](README.md) | [한국어](README.ko.md) | [日本語](README.ja.md) | [简体中文](README.zh-CN.md) | [Русский](README.ru.md)

Проверяйте обменные артефакты Context и Code офлайн, сравнивайте поддерживаемые версии контрактов и преобразуйте выбранные данные Code Ontology в артефакт `code-reference` с отчётом о потерянной или пропущенной информации.

Работает на macOS, Windows и Linux с Python 3.11 или новее. Не требует плагинов Code и Context, ключа API или удалённого сервиса.

## Установка

```text
codex plugin marketplace add battle-doll/ontology-companion-contracts
codex plugin add ontology-companion-contracts@ontology-contracts-preview
```

Устанавливайте плагин целиком, чтобы навык, сервер и схемы оставались совместимыми. После установки откройте новую задачу Codex в своём проекте, чтобы использовать установленные навыки.

## Применение к текущему разговору

```text
$apply-ontology-contracts
Примени Contracts к этому разговору и проверь выбранный context-export.json по профилю context-decision.
```

Навык использует доступный MCP-инструмент или проверенный комплектный CLI, связывает результат с реальным файлом и хешем его содержимого и продолжает текущую задачу. Без входного файла шаг остаётся незавершённым. Общий запрос выбирает только доступные для выполнения продукты; явно названные продукты имеют приоритет. Общая запись в текущем разговоре предотвращает повторное применение без изменения проекта или глобальных настроек. Для прямой проверки и преобразования по-прежнему используйте `$validate-ontology-contract`.

## Подключение проекта

В новой задаче Codex для нужного проекта отправьте:

```text
$validate-ontology-contract
Настрой локальное MCP-подключение этого плагина для текущего проекта.
```

После настройки откройте новую задачу в том же проекте для доступа к MCP-инструментам. Команды для ручной настройки, расположение установленного плагина и инструкции для разных ОС описаны в [руководстве по локальному MCP](docs/LOCAL_MCP.md) и [быстром старте для Windows](docs/WINDOWS_QUICKSTART.md).

## Использование

Замените имя файла на нужный файл в проекте:

```text
$validate-ontology-contract
Проверь context-export.json и объясни ошибки формата, если они есть.
```

Чтобы преобразовать выбранный снимок Code Ontology:

```text
$validate-ontology-contract
Преобразуй ontology.json в артефакт code-reference, выбрав путь src.
Покажи, какая информация пропущена при преобразовании.
Запроси у меня идентификатор репозитория или ревизию, если они нужны и отсутствуют во входных данных.
```

[Руководство по локальному использованию](docs/LOCAL_USE.md) описывает проверку, преобразование, сравнение версий и планирование миграции, включая команды CLI для работы без MCP. Преобразование через CLI может создать новый выходной файл, но не перезаписывает существующие.

Поддерживаемый формат обмена: `0.1.0-draft.1`, профили `context-decision` и `code-reference`. Преобразователь принимает данные Code Ontology Companion `0.6.0`: исходные снимки со схемой `1.0` и нативные артефакты `code-ontology-reference` версии `1.0.0`. Выбирайте нужные символы или пути; пропущенные данные отражаются в отчёте.

Проверяются структура и правила профиля. Результат не подтверждает достоверность содержания, соответствие указанной ревизии снимку или поведение кода во время выполнения. Ссылки на код не приводят к его выполнению, а удалённые схемы не загружаются. Для работы из облачного хоста нужно отдельно подключить локальную среду выполнения.

## Обновление

```text
codex plugin marketplace upgrade ontology-contracts-preview
codex plugin add ontology-companion-contracts@ontology-contracts-preview
```

После обновления откройте новую задачу Codex в своём проекте, чтобы загрузить обновлённые навыки. В этой задаче повторите запрос на подключение проекта выше, затем откройте ещё одну новую задачу для работы с обновлённым MCP-подключением.
